## S1. Test suite

cases on Python 3.13 including parametrised variants, and **2097 + 4 skipped**
on Python 3.9 (the skips are optional libraries absent from that environment,
not a behaviour difference). Statement coverage 98 %. The suite runs with the
socket layer stubbed out (`pytest -p tools.no_network`), so no test can reach
the network.

## S5. Downstream-tool compatibility

`bibliometrix::convert2df(dbsource="scopus")` executed on a file written by
`to_scopus_csv()` from a 14,302-record corpus: 14,302 rows imported, 0 dropped,
57 fields generated; `biblioAnalysis()` reports 31,984 authors. On a
three-database live corpus the institutional collaboration network resolves to
156 institutions. Index Keywords and References are written empty because no
source API supplies them; the consequence (index-keyword co-occurrence and
co-citation analyses unavailable) is stated rather than worked around.

Data: `bibliometrix_verification.json`.

## S6. Known limitations

1. The DOI arbiter defines a duplicate as one identifier, while Cochrane defines
   it as one study. Both precisions are reported; the choice is the review
   team's.
2. Records without a DOI cannot enter the ground truth (1.7 %-6.8 % per
   discipline), so a systematic failure confined to DOI-less records would be
   invisible to this protocol.
3. Retrieval was capped at 150 records per database per query to share the Web
   of Science daily budget; real reviews retrieve more, where cluster sizes and
   blocking pressure differ.
4. Per-discipline samples are 66-344 judgeable pairs. No confidence intervals
   are computed and none should be inferred.
5. The serial-instalment rule is English-only by construction.
6. VOSviewer and EmbedSLR compatibility is verified by column presence and
   position, not by executing those tools.
7. OpenAlex is absent from the design: no API key was available, and the service
   does not accept anonymous requests.
